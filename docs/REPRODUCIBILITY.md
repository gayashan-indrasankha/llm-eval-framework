# Reproducibility and integrity checklist

## Requirements

- Python **3.10+**, standard library only for code-based validation and analysis.
- For viewing the dashboard, an `.xlsx`-capable spreadsheet application. The workbook is a **reviewed report snapshot**, not automatically regenerated by the Python script.
- No Claude/Copilot credentials or paid API access are needed to run *local* checks; executing new model trials is a separate manual activity.

## Local checks (run from repository root)

```powershell
python scripts/validate_data.py
python -m unittest discover -s tests -p "test_*.py" -v
python scripts/stage3_analyze.py
```

Expected outcomes: **7 passing tests**, 12 cases, 48 rows and unique run IDs, 48 raw files, 12/12 archived prompt hashes, 48 human-approval labels, Claude **545/576**, Copilot **575/576**, and **44 blank execution timestamps**.

To save a fresh machine-readable metrics file without replacing the archived snapshot:

```powershell
python scripts/stage3_analyze.py --json stage3_recomputed_metrics.json
```

Review the metrics and remove the temporary file when finished, or store it outside the repository. The script exits with code 2 for certain data-integrity warnings, and source fixtures have additional regression tests.

## Prompt regeneration (optional; modifies files)

```powershell
python scripts/build_prompts.py
git diff -- generated/prompts generated/prompt_manifest.csv
```

Only regenerate when deliberately checking fixture reproducibility. If the synthetic policies or question text change, the prompt hashes change, and the historical evaluated prompts are no longer identical; those changes require a **new benchmark version**, not silent alteration of the 48-response evidence.

## Interpreting the checks

| Check | What it verifies | What it does not verify |
|---|---|---|
| File hash vs manifest | Local archived prompt bytes are consistent | Exact text pasted into live model UIs |
| Raw file presence | All expected response files are saved | UI provenance or unedited capture at generation time |
| Score audit | Each recorded score is 0–4 and the run matrix is complete | Independent scoring accuracy or absence of evaluator bias |
| Approval field | All 48 records contain project-owner approval labels | Independent third-party blind audit |
| Metric recomputation | The CSV reproduces the published totals | Model performance on real GRC questions |

## Evidence handling and public GitHub

The original synthetic response text files are deliberately **versioned**. Review public repository contents before pushing. Never add `.env` secrets, credentials, proprietary policy documents, identifiable company audit records or private evidence. Track unresolved metadata as missing; **do not infer the 44 absent timestamps** or hidden model identities.

Changes to the six-axis scoring or labels should be explained in a new review record and reapproved rather than overwriting historical decisions silently.
